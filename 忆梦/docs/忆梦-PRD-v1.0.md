### 1.2 术语名词释义

| 术语 | 英文/标识 | 释义 |
|---|---|---|
| 会话 | Session | 一个独立对话容器。含独立的角色、字卡归属、回复参数、群聊成员、聊天记录 |
| 角色 | Peer / Character | 与用户对话的一方。单聊时为 1 个角色，群聊时为多个「群成员」 |
| 群成员 | Member | 群聊中的单个角色。拥有独立的名称与头像，可被单独指定字卡（专属字卡） |
| 字卡 | Card | 用户自定义的一句话回复素材。是对方回复内容的唯一来源 |
| 字卡库 | CardStore | 全部字卡与分组的集合，分为「通用」与「专属」两个根 |
| 根 | Root | 字卡库的第一层分类。仅有两个：`通用`（全会话共用）、`专属`（某群成员独占） |
| 分组 | Group | 根内部的第二层分类。每个根有自己独立的一套分组，互不交叉 |
| 说话按钮 | Speak | 聊天页底部主按钮。点击后触发对方回复流程，用户无需输入内容 |
| 触发回复 | Reply Trigger | 从「点说话」或「主动发消息」开始，到对方消息落地的一次完整流程 |
| 回复组 | Reply Group | 一次触发中抽出的全部字卡消息集合（1~3 条，可配置） |
| 延迟回复 | Delay Reply | 对方在设定区间内随机挑选一个时刻发送消息 |
| 已读不回 | Read & Ignore | 一次触发中被判定为「不回复」，但消息仍标记为已读 |
| 主动发消息 | Active Message | 按分钟级间隔循环触发，无需用户操作 |
| 引用回复 | Quote Reply | 对方回复时引用用户近期 10 条消息中的 1 条 |
| 连句 | Merge Sentences | 把回复组的多条字卡用随机符号拼成 1 条消息，视觉上像一句话 |
| 正在输入指示器 | Typing Indicator | 延迟期间显示的「对方正在输入…」动画 |
| 数据快照 | Snapshot | 全量导出时的单个 JSON 文件，含全部会话、字卡、设置 |
| 运行时任务 | Runtime Task | 待执行的延迟回复/主动消息，持久化后可跨页面刷新恢复 |

## 2. 整体方案

### 2.1 项目名称与定位

- **项目名称**：忆梦
- **项目定位**：一个单人使用的、纯本地的「角色对话模拟」网站。把「和某个人说话」这件事做成可配置、可预演、可回味的桌面应用式体验。
- **解决的痛点**：
  1. 想说的话、想听到的回应，现实中不可控；在这里每一句回复都来自自己准备的字卡，既熟悉又偶有意外。
  2. 没有合适的工具能同时满足「自定义角色 + 自定义回复 + 自定义节奏 + 自定义群聊」且数据完全留在本机。
  3. 常见聊天模拟工具把功能全挤在一页，操作混乱；本项目用手机主屏 + 独立 APP 图标的方式把功能分层。

### 2.2 目标用户

- 唯一用户：网站所有者本人（单人使用、无账号、无分享需求）。
- 使用特征：移动端为主，随时打开、随时点一下「说话」看回复；偶尔进字卡库批量整理素材。

### 2.3 核心使用场景

| 编号 | 场景 | 描述 |
|---|---|---|
| S-01 | 随手一聊 | 打开网站 → 点桌面「忆梦」→ 点开某会话 → 点「说话」→ 等几秒看到对方回 1~3 条 → 关掉 |
| S-02 | 主动问候 | 不点说话，只挂着会话页，设定 30~90 分钟随机间隔，对方自己发来消息 |
| S-03 | 群聊 | 开启群聊后点说话，回复随机由不同成员发出，每个成员有独立头像名 |
| S-04 | 整理字卡 | 进「字卡库」→ 新建分组 → 批量粘贴 50 条（用 `【分组名】` 分块）→ 搜索去重 → 导出 txt 备份 |
| S-05 | 迁移/重置 | 在「设置」导出全部数据 JSON → 换设备导入 → 或一键清空重来 |

### 2.4 运行载体

| 项目 | 规定 |
|---|---|
| 载体 | 浏览器网页（Chrome / Edge 桌面版；手机浏览器可选） |
| 打开方式 | 直接双击 `index.html`，以 `file://` 协议运行；**不要求任何服务器或构建工具** |
| 布局基准 | 移动端优先；页面主体宽度限制 430px 并在屏幕内水平居中，高度撑满视口 |
| 断网能力 | 完全离线可用（除自定义字体 URL、外部图片 URL 等用户主动引入的外部资源） |

### 2.5 简要技术方向

纯静态 HTML + CSS + 原生 JavaScript（ES6+，不使用框架、不使用打包器），数据全部存于浏览器 `localStorage`，用 URL 参数跨页面传参，用全局事件 + BroadcastChannel 同步多页面数据。

### 2.6 项目核心目标

| 目标 | 可度量标准 |
|---|---|
| 打开即用 | 双击 index.html 到看到桌面 ≤ 1.5 秒（本地文件） |
| 交互零学习成本 | 从桌面到「点说话看到回复」，全程不超过 3 次点击 |
| 数据不丢 | 关闭页面/刷新/重开浏览器后，未完成的延迟回复仍能落地；所有设置与记录持久化 |
| 数据可迁移 | 全量 JSON 导出→清空→导入，数据 100% 还原 |
| 视觉一致 | 全部页面共用 1 套黑白灰 + 单色点缀的设计令牌，字体默认宋体，图标 100% 为 SVG |

## 4. 功能详细设计

> 通用约定：所有列表类页面底部操作按钮不超过 3 个；所有文本渲染前必须 `escapeHtml`；所有写库操作成功后派发 `ym:data` 事件。

### F-01 开场动画

- **功能目标**：进入桌面时给一次完整的、有质感的开场，建立「这不是普通网页」的仪式感。
- **用户操作步骤**：双击 index.html → 自动播放 → 点击任意位置可立即跳过。
- **交互逻辑**：
  1. 页面加载完成后立即进入开场态：黑色/白色底（跟随当前主题）→ 中央字形「忆梦」做 SVG 描边 + 遮罩擦除，随后散出 1 层柔光晕（径向渐变）。
  2. 总时长 2.2 秒；第 1.8 秒起桌面图标以 120ms 间隔逐枚淡入 + 上移 8px。
  3. 播放期间点击屏幕任意位置：立即跳到结束态（不重复播放）。
  4. 每次「页面加载」播放 1 次，不做每日限制。
- **状态切换**：`opening`（播放中，屏蔽所有点击）→ `done`（桌面可交互）。设置项 `开场动画开关` 关闭时直接进入 `done`。

### F-02 桌面图标网格

- **功能目标**：用手机主屏方式承载 3 个功能入口，替代「所有功能挤一页」。
- **用户操作步骤**：观看图标 → 点击图标 → 跳转对应页面。
- **交互逻辑**：
  1. 网格 2 列、图标尺寸 88×88、间距 24；图标为 SVG（图形 + 单色描边，风格统一），图标下方为宋体名称，字号 13px。
  2. 点击：图标轻微缩放（0.94，80ms）→ `location.href` 跳转。
  3. 桌面顶部左侧为主题切换按钮（日/夜/自动 三态循环），右侧信息区**不放小字注释**（按说明图要求：站内不写说明性小字）。
- **状态切换**：无。

### F-03 全局主题

- **功能目标**：支持日间/夜间/跟随系统三种模式，全站一致。
- **用户操作步骤**：点击桌面顶部主题按钮循环切换；或在设置页选择。
- **交互逻辑**：
  1. 三态顺序：`light → dark → auto`，按钮图标随态变化（太阳 / 月亮 / 半圆）。
  2. `auto` 模式读取系统：优先 `window.matchMedia('(prefers-color-scheme: dark)')`，变化时实时响应。
  3. 主题落地方式：`document.documentElement.dataset.theme = 'light'|'dark'`，颜色全部走 CSS 变量（`--bg / --panel / --text / --text-2 / --line / --accent`）。
  4. 单色点缀：整个站点只允许 1 个强调色（默认深靛 `#4B5BD6`，可在设置改为任意色值），仅用于「说话按钮」「已读标记」「选中态」。
- **状态切换**：`light ⇄ dark ⇄ auto`，写入设置即时持久化。

### F-04 数据自动保存与容量保护

- **功能目标**：任何操作后数据不丢；接近浏览器容量上限时提前警告。
- **交互逻辑**：
  1. 写库统一走 `ymSaveData()`，写入成功后派发 `ym:data` 事件（`detail: {scope}`）。
  2. 每次写入后计算当前占用（`JSON.stringify(data).length` 估算字节数）。
  3. 占用 > 4MB 时：桌面/聊天页顶部出现一次提示条「存储接近上限，建议导出备份」，同一天内最多提示 1 次。
  4. 写入抛出 `QuotaExceededError` 时：不写入、回滚内存副本、弹窗提示「存储已满：请先导出并清理历史消息」，并提供跳转设置页按钮。
- **状态切换**：`normal → warn(>4MB) → full(写入失败)`。

### F-05 会话列表

- **功能目标**：管理全部会话，看到每个会话的角色与最新状态。
- **用户操作步骤**：桌面点「忆梦」→ 进入列表 → 点会话卡片进入聊天 → 右上角「＋」新建。
- **交互逻辑**：
  1. 卡片结构：正方形圆角头像（SVG 默认占位或用户上传，首字兜底）→ 会话名（即角色名）→ 最后一条消息摘要（单行省略，超过 18 字截断）→ 相对时间（`刚刚 / N 分钟前 / N 小时前 / 昨天 / MM-DD`）。
  2. 群聊会话在名称右侧显示成员数徽标（如 `4`）。
  3. 卡片单击进入 `chat.html?sid=<id>`；长按/右键（桌面）或右上角「⋯」进入操作菜单：重命名、更换头像、复制会话、删除会话。
  4. 空状态：居中显示一行「还没有会话」+ 一个「新建」按钮。
- **状态切换**：点击态（缩放 0.97）；菜单态（`actionSheet` 打开/关闭）。

### F-06 新建会话

- **功能目标**：快速建立一个新角色会话，默认参数开箱可用。
- **用户操作步骤**：列表页「＋」→ 填名称 → 选头像（上传或默认）→ 确认。
- **交互逻辑**：
  1. 弹窗字段：名称（必填，1~20 字，默认「新会话」）、头像（可选，≤300KB 图片，Base64 存储）、是否开启群聊（默认关）。
  2. 确认后创建会话对象，默认参数：延迟 3~10 秒、回复条数 1~3、已读不回概率 30%、主动发消息关、引用回复开、连句关、音效开、通知开。
  3. 创建成功直接跳转 `chat.html?sid=<新id>`。
- **状态切换**：弹窗 `open/closed`；校验失败时按钮置灰并提示原因。

### F-07 会话重命名 / 删除

- **功能目标**：维护会话条目，删除时可控（避免误删聊天记录）。
- **交互逻辑**：
  1. 重命名：1~20 字，实时保存，列表与聊天页标题同步。
  2. 删除：二次确认弹窗文案「删除会话将同时删除其聊天记录，不可恢复」；确认后删除会话与对应的运行时任务；字卡不受影响。
  3. 删除后返回列表页，若当前正在该会话聊天页，则自动跳回列表页。
- **状态切换**：无。

### F-08 会话内角色名称 / 头像

- **功能目标**：每个会话拥有独立的角色身份。
- **交互逻辑**：
  1. 单聊：角色名与头像存于会话对象；群聊：由「群成员」决定，会话不单独设置角色。
  2. 聊天页标题显示角色名（单聊）或「会话名 + 成员数」（群聊）。
  3. 名称/头像是否展示由全局开关 F-27 控制，此处只存数据不控制显隐。
- **状态切换**：无。

### F-09 用户发送消息

- **功能目标**：用户能主动说一句话（可选行为，不影响「说话按钮」流程）。
- **用户操作步骤**：输入框输入文字 → 点「发送」（或键盘 Enter）→ 消息上线。
- **交互逻辑**：
  1. 输入框为单行自增高文本域，1~4 行，超过后内部滚动；上限 500 字，超出时禁止发送并提示。
  2. 点发送：立即创建用户消息（`role=user`）、清空输入框、播放发送音效（若开启）、消息流滚到底部。
  3. 用户在 2 秒内连续发送的多条消息，各自独立成条（不做合并）。
  4. 发送不触发对方回复（触发回复只由「说话」按钮或主动消息发起）。
  5. 空内容（全空白）禁止发送。
- **状态切换**：输入空（发送按钮置灰）→ 输入非空（可发送）；消息 `sending → sent`（本地写入即 `sent`，无网络态）。

### F-10 说话按钮触发回复

- **功能目标**：无需用户发消息，一键让对方开口，是核心玩法入口。
- **用户操作步骤**：点击底部主按钮「说话」→ 观察正在输入指示器 → 收到对方消息。
- **交互逻辑**：
  1. 点击后立即执行判定链（见 F-11~F-18），并对该次触发加锁：`triggerLock = true`，期间再次点击无效（提示「对方还在回应」），直到该组消息全部落地或判定为不回。
  2. 若本次会话可用字卡总数为 0：不进入判定，弹轻提示「这个会话没有可用字卡」，并给出「去字卡库」跳转。
  3. 若判定为「已读不回」：不产生消息，仅将最近 1 条用户消息（若有）置为已读；显示 1 次静默的「已读」状态更新。
  4. 判定为回复：进入 F-12 延迟流程。
- **状态切换**：`idle → locked → idle`。

### F-11 字卡随机抽取

- **功能目标**：从可用字卡中随机取值，保证内容多样性。
- **交互逻辑**：
  1. 可用字卡范围 = 当前会话的「通用」根全部未屏蔽字卡（未被屏蔽分组 + 未被屏蔽字卡）+ 若群聊则再加该成员「专属」根未屏蔽字卡（成员在 F-18 已确定）。
  2. 抽取条数 `n`：在 `[replyMin, replyMax]`（默认 1~3）区间内随机整数；若可用字卡总数 < n，则 `n = 可用总数`。
  3. 抽取方式：**不放回随机**（同一次回复组内不重复）。所有字卡权重相同（P1 才做权重）。
  4. 抽出的字卡按抽取顺序排列，作为本组的「内容序列」。
- **状态切换**：无。异常：可用数 0 → 按 F-10 第 2 条处理。

### F-12 延迟随机回复

- **功能目标**：模拟真人的思考与打字节奏。
- **交互逻辑**：
  1. 每条消息独立延迟：第 `i` 条消息的发送时刻 `t_i = now + randInt(delayMin, delayMax) * 1000 + i * gap`，其中 `gap` 固定 600ms，用于保证多条按顺序落地、不重叠。
  2. 延迟区间 `[delayMin, delayMax]` 为会话级参数，单位秒，默认 3~10，可配范围 1~120，且必须 `delayMin ≤ delayMax`。
  3. 延迟期间显示正在输入指示器（F-17）；该组全部落地后指示器消失、`triggerLock` 解除。
  4. 延迟任务写入运行时任务表（`ym_runtime_v1`），见 F-26 与 5.4。
- **状态切换**：`pending → firing → delivered`。

### F-13 已读不回

- **功能目标**：让对话有"看了没回"的真实感。
- **交互逻辑**：
  1. 概率参数 `skipChance`（0~100%，默认 30%），会话级。
  2. **判定粒度**：每次「说话」触发时掷一次骰子（`Math.random() * 100 < skipChance`），命中则整组不回复。
  3. 命中后仍执行已读：把该会话中最后一条用户消息的 `readStatus` 置为 `read`；若无用户消息则无操作。
  4. 主动发消息（F-14）也使用同一概率判定，命中则该轮不发。
  5. 若 `skipChance = 100`：永不回复，但每次点说话都会刷新最后一条用户消息的已读时间。
- **状态切换**：无。

### F-14 主动发消息

- **功能目标**：不点说话，对方也按节奏自己找上门。
- **交互逻辑**：
  1. 会话级开关 `activeEnabled`；参数 `[activeMinMin, activeMaxMin]` 分钟区间，默认 30~90，可配 1~1440。
  2. 开启后：计算下一次触发时刻 `t = now + randInt(activeMin, activeMax) * 60000`，写入运行时任务。
  3. 到点后：走「已读不回判定 → 抽卡 → 延迟区间 → 依次落地」同一套流程（与说话按钮**完全独立**，互不打断、互不重置）。
  4. 一轮完成（或被判定不回）后，立即安排下一轮，形成循环；关闭开关时清除未执行的主动任务。
  5. 页面上必须有可视状态：聊天页顶部参数区显示「主动消息 · 下一条约 N 分钟后」。
  6. 限制（如实写入交付说明）：浏览器关闭期间无法真正"后台运行"；重新打开时若已超出预定时刻，最多补发 1 组，并重新排下一次。
- **状态切换**：`off → armed → firing → armed`。

### F-15 引用回复

- **功能目标**：让对方的回复"接得上"用户刚说的话。
- **交互逻辑**：
  1. 会话级开关 `quoteEnabled`（默认开）。
  2. 触发时：从会话内**最近 10 条用户消息**中随机抽 1 条作为引用对象；不足 10 条则从现有全部用户消息中抽。
  3. 若会话内没有任何用户消息：本次不引用，正常回复。
  4. 引用落地：该回复组的**第 1 条**消息携带 `quotedMessageId`（D-01 暂定规则；连句开启时为合并后那条）。
  5. 显示：气泡上方一个引用块——左侧 2px 强调色竖线 + 引用文本（最多 2 行省略，字号小一号，颜色 `--text-2`），下方为正文。
  6. 被引用的源消息被删除时，引用块文本置为「消息已删除」，不报错。
- **状态切换**：无。

### F-16 连句

- **功能目标**：把多条字卡拼成"一口气打出来的一句话"，观感更真实。
- **交互逻辑**：
  1. 会话级开关 `mergeEnabled`（默认关）。
  2. 开启后，回复组抽取的 n 条字卡按顺序拼接为 1 条消息：`part1 + 符号 + part2 + …`，符号从 `mergeSymbols` 数组中随机取。
  3. `mergeSymbols` 默认 `['，', '、', '。', ' ', '～']`，可在设置中增删（每项 1~3 字符，最少保留 1 项）。
  4. 合并后仍算 1 条消息，占 1 次延迟；连句开启时 `gap` 不生效（因为只有 1 条）。
  5. 若 n = 1，则不拼接，直接发出。
- **状态切换**：无。

### F-17 正在输入指示器

- **功能目标**：延迟期间给出"对方在打字"的实时反馈。
- **交互逻辑**：
  1. 形态：对方气泡位置的浅色占位气泡，内容为【自定义文案】+ 三点跳动动画（1.2s 循环，透明度 0.3→1）。
  2. 自定义文案 `typingText`：全局设置项，默认「正在输入…」，上限 20 字。
  3. 群聊时显示为「【成员名】正在输入…」的形态（若开关为关闭名称则只显示文案）。
  4. 多条消息排队时，指示器在整组期间持续显示，不随单条落地消失。
  5. 页面失焦不停止显示（本地无"对方"概念，按仍在等待处理）。
- **状态切换**：`hidden → visible → hidden`。

### F-18 群聊成员分配

- **功能目标**：一个会话里有多个人，各自说各自的。
- **交互逻辑**：
  1. 会话级开关 `groupEnabled`；开启条件：该会话绑定的成员数 ≥ 2，否则开关置灰并提示。
  2. **成员分配时机**：一次回复组抽取完成后，从成员中随机选 1 名，**整组绑定同一成员**（营造"这个人在连续打字"）。
  3. 每条消息记录 `memberId` 与该成员当时的 `name/avatar` 快照；成员后续被删除或改名，历史消息仍显示当时的快照。
  4. 群聊消息在气泡上方显示成员名（受 F-27 名称开关控制）+ 头像（受头像开关控制，显示在气泡左侧）。
  5. 单聊不显示成员名。
  6. 专属字卡归属：抽取该成员时，可用范围追加该成员的专属字卡（见 F-11 第 1 条）。
- **状态切换**：`group off / group on`。

### F-19 时间戳显隐

- **功能目标**：默认干净，需要时点一下就能看到这条是什么时候发的。
- **交互逻辑**：
  1. 全局开关 `showTimestamp`（默认关）：关闭时**任何消息都不显示时间**，点击消息也不显示。
  2. 开启时：常态隐藏；**单击某条消息** → 仅该条下方显示时间（`HH:mm`，同日；跨日追加 `MM-DD`），再点其他消息则上一条自动隐藏。
  3. 点击消息同时会打开该条的操作浮层（见 F-21/F-23），时间戳与操作浮层同时出现。
  4. 点击消息流空白区域：关闭所有时间与浮层。
  5. 消息流顶部「日期分隔条」始终显示（`YYYY年MM月DD日`），不受开关影响——否则跨天记录无锚点。
- **状态切换**：`collapsed（全部隐藏） → focused（单条显示）`。

### F-20 已读状态显示

- **功能目标**：让"对方看到了"这件事有视觉落点。
- **交互逻辑**：
  1. 全局开关 `showReadStatus`（默认开）；已读文字样式可在设置中选 `文字"已读"` / `双勾图标` / `圆点`（默认文字）。
  2. 已读标记只作用于**用户消息**，显示在气泡右下角，字号 11px，颜色 `--text-2`。
  3. 状态来源：① 对方成功回复（该组落地时，把用户最后一条消息置 `read`）；② 已读不回命中（F-13 第 3 条）。
  4. 未读用户消息不显示任何标记（不做"未读"字样）。
- **状态切换**：`none → read`。

### F-21 删除单条消息

- **功能目标**：删掉不想要的某一句话，可精确到单条。
- **交互逻辑**：
  1. 入口：单击消息 → 操作浮层（气泡上方小胶囊条）→ 点「删除」。
  2. 删除：二次确认「删除这条消息？」→ 从会话消息数组移除 → 保存 → 派发事件刷新。
  3. 被删除消息若被其它消息引用：引用块文本置为「消息已删除」（见 F-15 第 6 条）。
  4. 被删除消息若为运行时任务的目标（尚未落地），则任务立即作废。
  5. 删除后消息流保持滚动位置，不跳顶。
- **状态切换**：`present → deleted`。

### F-22 清空会话消息

- **功能目标**：一次性清掉某个会话的全部聊天记录（保留会话本身与参数）。
- **交互逻辑**：
  1. 入口：聊天页底部「更多」菜单 →「清空聊天记录」。
  2. 二次确认文案：`清空后不可恢复，会话与字卡不受影响`。
  3. 执行：清空 `messages`、作废该会话全部运行时任务、关闭指示器与浮层。
- **状态切换**：无。

### F-23 点击自己消息加入字卡库

- **功能目标**：把说过的话直接变成对方的回复素材，并允许先修饰。
- **交互逻辑**：
  1. 单击自己的消息 → 浮层出现「加入字卡」与「删除」。
  2. 点「加入字卡」→ 弹窗：预填该消息原文（可编辑，上限 200 字）→ 选择目标（默认「通用 · 默认分组」，可切换根与分组；群聊时可选某成员专属）→ 确认。
  3. 校验：目标根内已存在完全相同文本 → 提示「已存在相同字卡，未重复添加」。
  4. 成功：写入字卡、轻提示「已加入字卡库」、浮层关闭。
  5. 从设置「字卡库」页面进入的同一弹窗可复用（用于批量/单条添加）。
- **状态切换**：`浮层 → 编辑弹窗 → 完成`。

### F-24 聊天背景

- **功能目标**：把聊天页换成自己的底色，兼顾氛围与可读性。
- **交互逻辑**：
  1. 设置项：`聊天背景`（全局默认）+ 会话级覆盖（会话参数区可"使用自定义背景"）。
  2. 三种来源：① 纯色（色值）② 图片上传（≤500KB，Base64）③ 图片 URL（http/https；`file://` 下若加载失败则回退纯色并不报错）。
  3. 应用方式：作为聊天页背景层 `background-size: cover; background-position: center`，其上叠加一层可调透明度的遮罩（默认 88%，保证文字对比度）。
  4. 移除背景：恢复为 `--bg`。
- **状态切换**：`none → color → image`。

### F-25 消息音效

- **功能目标**：每条消息落地时有声音反馈，且声音可以自定义、可随机。
- **交互逻辑**：
  1. 全局开关 `soundEnabled`（默认开）+ 会话级开关（默认继承全局）。
  2. 音效列表：用户可上传音频（mp3/wav/ogg，单个 ≤200KB，最多 10 条），也内置 3 条默认音效（用 WebAudio 合成的短促「叮」声，避免依赖外部文件）。
  3. 播放规则：`randomSound` 开关打开时从已启用的音效中随机取 1 条播放；关闭时固定播放第 1 条。
  4. 触发时机：对方消息落地时播放；用户发送消息时也播放（用户音效与对方音效可分别指定，默认「对方=列表随机、用户=列表第 1 条」）。
  5. 首次交互前不得自动播放（浏览器策略）；聊天页在用户第一次点击（说话/发送/进入页面）后解锁音频上下文。
  6. 音频存储：小文件转 Base64 存库；超过限制的上传直接拒绝并提示。
- **状态切换**：`locked（未解锁） → ready`。

### F-26 通知（页内降级）

- **功能目标**：在用户没盯着聊天页时给出提醒；在 `file://` 限制下用页内方式实现。
- **交互逻辑**：
  1. 全局开关 `notifyEnabled`（默认开）；会话级可继承。
  2. 触发条件：对方消息落地时，若 `document.hidden === true` 或窗口失焦，则：
     - 页面顶部滑入提示条：`【角色名/成员名】发来一条消息`，3 秒自动收起，点击可直接跳到该会话；
     - 标题变成 `● 新消息 · 忆梦`，回到页面聚焦时恢复。
  3. `document.hidden` 不可用（部分 `file://` 环境）时：只要页面失焦（`blur`）就视为后台。
  4. 真·系统通知（Notification API）作为 P1-01 预留：设置项存在但标注「需挂 localhost」，`file://` 下点击该项提示原因，不报错。
- **状态切换**：`inactive → banner(s) → inactive`。

### F-27 名称 / 头像显示开关

- **功能目标**：控制对话区视觉密度。
- **交互逻辑**：
  1. 全局设置项 `showName`（默认开）、`showAvatar`（默认开）。
  2. 关闭头像：气泡上移占满行宽，内容不变；关闭名称：群聊不再显示成员名，单聊本就不显示。
  3. 两开关互相独立，可任意组合；变更后聊天页即时生效（无需刷新）。
- **状态切换**：无。

### F-28 字号 / 字体 / 气泡自定义

- **功能目标**：整体观感按用户喜好调。
- **交互逻辑**：
  1. **字号**：滑块 12~22px，步进 1，默认 15（作用于消息正文；标题按比例缩放 1.15 倍）。
  2. **系统字体**：两种方式——
     - CSS 方式：输入字体族字符串（如 `"Songti SC", serif`），直接写入 `--font-family`；
     - URL 方式：输入字体文件 URL（woff/woff2/ttf），动态生成 `@font-face` 后使用；加载失败自动回退默认宋体并提示一次。
     - 默认值：`"SimSun", "Songti SC", "Noto Serif CJK SC", serif`。
  3. **气泡**：预设 4 套模板（`圆角方 / 胶囊 / 直角 / 描边`）+「自定义」；自定义输入框接受 CSS 声明片段（如 `border-radius: 18px 18px 4px 18px; padding: 8px 12px; backdrop-filter: blur(4px);`），保存前过滤 `</style>`、`javascript:`、`expression(`、`url(`，命中则拒绝并提示「自定义内容含不安全写法」。
  4. 作用范围：用户与对方气泡可分别设置（对方默认与用户同步，可单独覆盖）。
  5. 全部设置实时预览，无需重启。
- **状态切换**：无。

### F-29 字卡库总览

- **功能目标**：字卡库的唯一入口，两个根一眼分清。
- **用户操作步骤**：桌面点「字卡库」→ 顶部切换 `通用 / 专属` → 查看分组与字卡。
- **交互逻辑**：
  1. 顶部为分段控件（Segmented）：`通用（N）` / `专属（N）`，N 为该根字卡总数（不含屏蔽）。
  2. 「专属」根进入后：先选成员（成员横向滚动头像条，来自全局成员表），再显示该成员的分组与字卡；无成员时显示「先在设置里添加群成员」。
  3. 分组以折叠列表呈现：分组名 + 字卡条数 + 折叠箭头；展开后展示字卡行（文本单行省略，点击进入编辑）。
  4. 屏蔽状态的字卡/分组以 50% 透明度 + 「已屏蔽」小标签呈现，仍可见可操作。
- **状态切换**：根切换；分组 `collapsed/expanded`。

### F-30 分组管理

- **功能目标**：在根内部建立可无限嵌套的逻辑分类（本期固定为「根 → 分组」两级，不做多级嵌套）。
- **交互逻辑**：
  1. 新建分组：输入名称（1~12 字，同根内重名不允许）；新建后自动展开。
  2. 重命名、删除分组：删除分组需二次确认，文案「删除分组后其下 N 条字卡将被一并删除」；确认后连字卡一起删。
  3. 每个根内置一个「默认分组」（`id=g_default`，不可删除、可改名、可屏蔽）；新字卡未指定分组时进入该组。
  4. 分组排序：按 `order` 字段手工排序（上移/下移按钮），也支持「按名称」「按字卡数」一键排序。
- **状态切换**：无。

### F-31 字卡添加（单条 / 批量）

- **功能目标**：能一条条加，也能一次贴几十条。
- **交互逻辑**：
  1. **单条**：底部「＋」→ 输入文本（1~200 字）→ 选分组 → 保存。同根内完全重复（trim 后完全相等）则拒绝并提示。
  2. **批量**：弹出一个多行文本域（上限 5000 字），语法规则：
     - 以 `【分组名】`独占一行开头，其后每行一条字卡归入该分组；
     - 若 `【分组名】` 对应的分组不存在，**自动创建**；
     - 文件/文本开头没有 `【分组名】` 的行，归入「默认分组」；
     - 空行忽略；行首尾空白自动 trim；
     - 单行超过 200 字：截断为 200 字并计入「超出被截断 N 条」的提示。
  3. 提交前显示预览：将创建 N 个分组、新增 M 条字卡、跳过重复 K 条；用户确认后一次性写入。
  4. 自动去重：批量内重复与库内重复都跳过，结束后提示统计。
- **状态切换**：`编辑 → 预览 → 写入`。

### F-32 字卡编辑 / 删除

- **交互逻辑**：
  1. 点击字卡行进入编辑态（行内编辑或弹窗，采用弹窗）：可改文本、改分组（下拉）。
  2. 删除单张：行内左滑/按钮「删除」→ 直接删除（不二次确认，但操作后 5 秒内可在提示条点「撤销」恢复）。
  3. 批量删除：进入「批量管理」模式，勾选多条 → 底部「删除所选」，二次确认。
- **状态切换**：`浏览 → 编辑/批量选择`。

### F-33 排序 / 搜索 / 去重

- **交互逻辑**：
  1. **排序**：选项 `手动（默认）/ 最近添加 / 文本长度 / 字母`；仅作用于当前根当前成员视图。手动排序通过长按拖动（移动端）或上下移动按钮（更稳，二者取按钮，交付时也可两者并存）。
  2. **搜索**：顶部搜索框（防抖 200ms），按包含匹配当前根内全部字卡文本；命中高亮片段；无结果显示「没有匹配的字卡」。
  3. **自动去重**：
     - 写入时自动执行（单条/批量/导入均查重）；
     - 提供「全库去重」按钮：对当前根做一次去重，保留最早创建的一条，删除其余（含跨分组重复），执行前显示「将删除 N 条重复字卡」并二次确认；
     - 去重判定标准：`trim` 后**完全相等**（区分全/半角外的所有差异；不区分大小写）。
- **状态切换**：`sort default ⇄ changed`。

### F-34 移动字卡到其它分组

- **交互逻辑**：
  1. 单条移动：字卡弹窗内的「分组」下拉，选新分组即保存。
  2. 批量移动：批量选择后底部「移动到…」→ 选目标分组 → 一次性更新 `groupId`。
  3. 跨根移动不允许（通用 ↔ 专属不可直接移动，需复制后删除，交付说明中注明）。
- **状态切换**：无。

### F-35 屏蔽字卡 / 屏蔽分组

- **功能目标**：暂时不想让某句话出现，但不想删。
- **交互逻辑**：
  1. 字卡行右侧「眼睛」图标切换 `hidden`；分组长按/菜单切换 `hidden`。
  2. 被屏蔽字卡不参与抽取（F-11 第 1 条）；被屏蔽分组内的所有字卡均不参与抽取，且该分组内单卡的开关状态不叠加生效（分组屏蔽优先）。
  3. 屏蔽不改变排序与搜索可见性（仍可见，仅淡化显示）。
  4. 顶部显示当前根屏蔽统计：`已屏蔽 X 条 / Y 组`。
- **状态切换**：`visible ⇄ hidden`。

### F-36 专属字卡绑定成员

- **交互逻辑**：
  1. 成员来源：设置页「群成员管理」中的全局成员表（新增/改名/换头像/删除）。
  2. 「专属」根按成员分区，每个成员下独立一套分组与字卡（结构同通用，两层）。
  3. 只有该成员被群聊随机选中时，其专属字卡才进入抽取池；单聊不使用专属字卡。
  4. 删除成员：其专属字卡进入「孤立专属」区（成员区显示为「已删除成员」），可批量删除或迁移（P1 迁移到其它成员）。
- **状态切换**：无。

### F-37 字卡库导入 / 导出

- **功能目标**：字卡可带走、可备份、可手改。
- **交互逻辑**：
  1. **导出**：选择导出范围（当前根 / 当前成员专属 / 全库）→ 生成 `.txt` 并下载，文件名为 `忆梦字卡_通用_2026-11-08.txt`。
  2. txt 格式与 F-31 批量语法完全一致：
     ```
     【分组名A】
     字卡1
     字卡2
     【分组名B】
     字卡3
     ```
     专属导出时，文件头追加一行 `#成员:成员名`（导入时可选择"s强制归属某成员"）。
  3. **导入**：选择 txt → 解析 → **预览确认**（将新建分组 N 个、新增 M 条、跳过重复 K 条、被忽略的非法行 L 条）→ 选择导入到「通用 / 某成员专属」→ 确认写入。
  4. 编码：读取时按 UTF-8 解析；若检测到乱码（含替换字符 `\uFFFD`）则提示「文件编码可能不是 UTF-8，请另存后重试」。
  5. 单次导入上限 3000 条。
- **状态切换**：`选择文件 → 预览 → 完成`。

### F-38 设置中心结构

- **交互逻辑**：分区列表（可折叠），顺序固定：
  1. 外观 — 主题、字号、字体（CSS/URL）、气泡、聊天背景、名称/头像/时间戳/已读显示开关、已读样式
  2. 聊天体验 — 正在输入文案、连句符号表、音效（开关/列表/随机）
  3. 通知 — 页内提示开关、真·系统通知（P1 置灰）
  4. 群成员 — 成员列表（新增/编辑/删除）
  5. 数据 — 全量导出 / 全量导入 / 容量查看 / 重置
  6. 关于 — 版本号、数据位置说明
- **状态切换**：分区 `collapsed/expanded`。

### F-39 全量数据导入导出

- **交互逻辑**：
  1. **导出**：一键生成 `忆梦_全量备份_YYYYMMDD_HHMM.json`，内容为完整数据快照（见 5.5）。
  2. **导入**：选择 JSON → 校验结构（`version`、`sessions`、`cardStore` 必须存在且类型正确）→ 显示摘要（会话数、消息数、字卡数、导出时间）→ 选择「覆盖现有数据」或「取消」。
  3. 覆盖前自动把当前数据另存为 `ym_data_backup_auto`（保留最近 1 份），允许在设置页「恢复上一次自动备份」。
  4. 导入成功后重新加载页面，避免半旧半新的内存态。
  5. 版本不匹配（`version` 高于当前）：提示「备份来自更高版本，可能不兼容」，允许继续但风险自担。
- **状态切换**：`idle → 校验中 → 摘要 → 导入完成`。

### F-40 重置所有数据

- **交互逻辑**：
  1. 入口：设置 → 数据 → 「重置所有数据」（红色文字按钮）。
  2. 二次确认：输入框要求手输 `重置` 两个字，才激活确认按钮；提示「所有会话、消息、字卡、设置将被清空」。
  3. 执行：清空 `ym_data_v1` 与 `ym_runtime_v1`，回到初始状态（保留自动备份，便于反悔）。
  4. 完成后跳回桌面并播放一次开场动画。
- **状态切换**：无。

- 本期仅在设置页保留对应开关入口（置灰 + 一行说明为什么暂不可用），不做实现：系统通知、条数上限扩展、字卡权重、撤回、语音/图片消息、云同步、会话模板。

## 5. 技术设计

### 5.1 技术栈清单

| 类别 | 选型 | 说明 |
|---|---|---|
| 语言 | HTML5 / CSS3 / JavaScript (ES2020) | 无框架、无打包、无 npm 依赖 |
| 页面拆分 | 5 个独立页面（index / sessions / chat / cards / settings） | 遵循「一功能一套 html+js+css」规则 |
| 样式 | CSS 变量（设计令牌）+ 少量自定义属性组合 | 主题切换只改变量，不重写样式 |
| 图标 | SVG（内联或 `assets/icons/*.svg`） | 全部矢量，不引第三方图标库 |
| 存储 | `localStorage` | 5MB 级容量，需容量保护 |
| 跨页同步 | `window` 自定义事件 + `BroadcastChannel('ym')` + `storage` 事件兜底 | 三个通道任一到达即刷新 |
| 音频 | WebAudio（内置音效）+ `HTMLAudioElement`（自定义 Base64 音效） | 首次交互解锁音频上下文 |
| 文件导入导出 | `Blob` + `URL.createObjectURL` + `FileReader` | 纯前端，无上传 |
| 字体 | `@font-face` 动态注入（URL 方式）/ CSS 字体族字符串 | 失败回退默认宋体 |
| 时间处理 | 原生 `Date` | 不引入 dayjs 等库 |
| 无 | 不使用 IndexedDB（P1 若容量不足再迁移） | 本期单 key 结构便于导出 |

> 原生实现已足够覆盖全部功能；引入第三方库会破坏 `file://` 双击可用与零依赖原则。

### 5.4 数据存储方案

| Key | 内容 | 写入时机 | 大小预估 |
|---|---|---|---|
| `ym_data_v1` | 全量业务数据（设置 / 会话 / 消息 / 字卡 / 成员 / 外观） | 任何业务写操作后 | 空库约 3KB；1000 条消息约 200KB |
| `ym_runtime_v1` | 未完成的延迟任务数组 | 任务创建 / 执行 / 作废时 | < 5KB |
| `ym_data_backup_auto` | 导入或重置前的自动备份（保留最近 1 份） | 导入 / 重置前 | 同全量数据 |

规则：
1. 写入前做「读-改-写」：`YM.store.get()` 取最新对象 → 修改 → `YM.store.save()`，避免页面持有过期副本。
2. `ym_data_v1` 采用**单 key 整体写入**，保证导入导出的原子性；不做分片。
3. 迁移：数据对象带 `version` 字段，`YM.store.migrate()` 在读取时按版本号补齐缺省字段（v1 为首版，仅预留函数）。
4. 容量计算：`new Blob([JSON.stringify(data)]).size` 返回真实字节数。

#### 5.7.4 任务调度 `YM.task`

| 函数 | 入参 | 出参 | 规则 |
|---|---|---|---|
| `schedule(plan, sessionId)` | `PlanResult,string` | `Task[]` | 每条消息生成 1 个 `reply` 任务，写入 `ym_runtime_v1` |
| `scheduleActive(sessionId)` | `string` | `Task` | 按 `activeMin/Max` 计算下一轮 `active` 任务 |
| `resume()` | 无 | `{delivered:number, dropped:number}` | 页面加载时扫描过期任务；过期 `reply` 立即落地（同会话最多连补 3 条），过期 `active` 最多补 1 组 |
| `cancel(sessionId)` | `string` | `number` | 作废该会话全部任务，返回数量 |
| `cancelMessage(id)` | `string` | `boolean` | 消息被删除时作废其对应任务 |
| `timerLoop()` | 无 | 无 | 每 500ms 检查一次，命中则执行并清除 |

并发规则：同一会话同一时刻只允许 1 个 `triggerId` 处于活动态（`triggerLock` 记录在内存 + 任务的 `triggerId` 比对）。

### 5.8 关键流程（引擎内部顺序，不可调换）

```
点「说话」
 → ① 锁定检查（已有活动触发 → 返回 locked）
 → ② 取可用字卡池（空 → empty_pool，提示并结束）
 → ③ 掷「已读不回」：命中 → 把最后一条用户消息置已读 → 解锁 → 结束
 → ④ 随机条数 n（1~replyMax，且 ≤ 池容量）→ 不放回抽 n 条
 → ⑤ 群聊：随机选 1 名成员，整组绑定
 → ⑥ 连句：n 条合并为 1 条（取随机符号），否则保持 n 条
 → ⑦ 引用：抽近 10 条用户消息 → 赋予第 1 条消息
 → ⑧ 生成延迟序列 → 写入运行时任务
 → ⑨ 显示正在输入指示器 → 到点逐条落地 → 播放音效/通知 → 全部落地后解锁
```

## 6. 异常处理机制

| 编号 | 场景 | 触发条件 | 处理逻辑 | 用户可见反馈 |
|---|---|---|---|---|
| E-01 | localStorage 不可用 | 隐私模式/被禁用，`setItem` 抛错 | 降级为内存态运行（关闭页面即丢），并禁止「导入/导出以外的持久化承诺」 | 首次进入弹一次提示「当前浏览器禁止本地存储，数据无法保存」 |
| E-02 | 存储写满 | `QuotaExceededError` | 回滚内存副本、不写入、引导导出与清理 | 弹窗「存储已满」+ 快捷跳到设置·数据 |
| E-03 | 备份 JSON 结构损坏 | `importAll` 校验失败 | 拒绝导入，原数据不动 | 「备份文件格式不正确，未做任何修改」 |
| E-04 | 备份版本过高 | `json.version > '1.0'` | 允许导入但提示风险 | 「备份来自更高版本，可能不兼容」 |
| E-05 | 字卡池为空 | 点说话 / 主动触发 | 不产生消息，不循环空转（主动模式自动暂停并提示） | 轻提示「这个会话没有可用字卡」+ 「去字卡库」 |
| E-06 | 输入超限 | 用户消息 > 500 字 / 字卡 > 200 字 | 禁止提交，保留已输入内容 | 输入框下方红字「最多 500 字，当前 N 字」 |
| E-07 | 图片/音频超限 | 头像 > 300KB、背景 > 500KB、音效 > 200KB | 拒绝保存，不压缩、不静默截断 | 「文件超过 N KB，请压缩后重试」 |
| E-08 | 字体 URL 加载失败 | `@font-face` 报错或超时 5s | 回退默认宋体 | 提示一次「自定义字体加载失败，已使用默认字体」 |
| E-09 | 聊天背景 URL 失效 | 图片 `onerror` | 回退纯色背景 | 无弹窗，仅在设置项旁标「加载失败」 |
| E-10 | 引用源消息被删 | 渲染消息时 `quotedMessageId` 不存在 | 引用块显示「消息已删除」 | 同上 |
| E-11 | 群聊成员不足 | 开启群聊时绑定成员 < 2 | 拒绝开启 | 「群聊至少需要 2 名成员」+ 跳设置 |
| E-12 | 成员被删除后有专属字卡 | 删除成员 | 专属区标记「已删除成员」，抽取时不参与 | 字卡库可见该区，标注「已删除成员」 |
| E-13 | 页面在任务执行中被关闭 | 关闭浏览器/切页 | 任务留在 `ym_runtime_v1`；下次加载恢复 | 恢复时补发消息，不弹窗 |
| E-14 | 系统时间被回拨 | `fireAt` 远大于当前时间 | 任务照常等待；若差值 > 24h 则重算 `fireAt` | 无提示（静默修正） |
| E-15 | 重复点击说话 | 活动触发未结束 | 加锁，第二次点击无效 | 「对方还在回应」轻提示 |
| E-16 | 删除正在等待的消息 | 用户删除某条用户消息且其被引用 | 引用块降级；不影响任务 | 「消息已删除」 |
| E-17 | 连句符号列表为空 | 用户删光符号 | 强制保留 1 项（删除最后一个时置灰） | 按钮置灰 + 「至少保留 1 个符号」 |
| E-18 | 会话被删而任务未完成 | 删除会话 | 连带 `YM.task.cancel(sessionId)` | 无 |
| E-19 | txt 编码非 UTF-8 | 解析出现 `\uFFFD` | 中止导入并保留原文不变 | 「文件编码可能不是 UTF-8」 |
| E-20 | 导入条数超限 | 单次 > 3000 条 | 只导入前 3000 条并提示 | 「已导入前 3000 条，其余请分批导入」 |
| E-21 | 自定义 CSS 含危险写法 | 命中 `</style>`、`javascript:`、`expression(`、`url(` | 拒绝保存 | 「自定义内容含不安全写法，已拒绝」 |
| E-22 | BroadcastChannel 不可用 | 旧版本浏览器 | 仅用 `storage` 事件 + 页面内事件 | 无提示 |
| E-23 | 主题自动模式 API 缺失 | 无 `matchMedia` | 固定为 `light` | 无提示，主题按钮 auto 态标注不可用 |
| E-24 | 音频未解锁即播放 | 首屏未交互 | 静默跳过播放，等首次交互后恢复 | 无提示 |
| E-25 | 变量缺失/旧数据 | 旧版数据结构缺字段 | `migrate()` 补默认值，不报错 | 无提示 |

### A.2 点「说话」的完整判定链

```
点「说话」
 │
 ├─ 已有活动触发？ ── 是 → 提示「对方还在回应」，结束
 │
 ├─ 可用字卡池为空？ ── 是 → 提示「没有可用字卡」，结束
 │
 ├─ 掷已读不回（skipChance）
 │      └─ 命中 → 最后一条用户消息置已读 → 结束（无消息）
 │
 ├─ 随机条数 n（1~replyMax，≤ 池容量）
 ├─ 不放回抽 n 条字卡
 ├─ 群聊？ → 随机选 1 名成员，整组绑定
 ├─ 连句？ → n 条合并为 1 条（随机符号）
 ├─ 引用？ → 从近 10 条用户消息随机 1 条，赋予第 1 条
 ├─ 生成延迟序列（每条独立随机 + 顺序间隔 600ms）
 └─ 写入运行时任务 → 显示「正在输入…」
        ↓ 到点
   逐条落地（音效 + 通知 + 滚动到底）
        ↓ 全组完成
   解除锁定 → 等下一次点「说话」
```

### A.3 主动发消息循环

```
开启主动消息
    ↓
计算 fireAt = now + rand(activeMin, activeMax) 分钟
    ↓ 保存为 runtime task
到点 → 走「已读不回 → 抽卡 → 延迟 → 落地」同一流程
    ↓ 本组结束
再排下一次（循环）
    ↓ 关闭开关
清除未执行的 active 任务
```

### A.4 字卡批量添加

```
粘贴文本
    ↓
逐行解析
 ├─ 【X】 行 → 记录当前分组（不存在则标记待创建）
 ├─ 普通行 → 添加到当前分组（默认分组的初始值）
 └─ 空行 → 忽略
    ↓
查重（库内 + 本次内）+ 截断超 200 字
    ↓
预览：新建 N 组 / 新增 M 条 / 跳过 K 条 / 截断 J 条
    ↓ 确认
一次性写入 → toast 统计 → 列表刷新
```

### A.5 数据迁移

```
设置·数据
 ├─ 导出：拼装快照 → Blob → 下载 忆梦_全量备份_时间.json
 ├─ 导入：选择文件 → JSON 校验 → 显示摘要 → 自动备份当前 → 覆盖 → 重载页面
 ├─ 恢复自动备份 → 同上（覆盖）
 └─ 重置：输入「重置」→ 自动备份 → 清空 → 跳桌面
```
